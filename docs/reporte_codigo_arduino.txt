4. MODULO GIROSCOPIO MPU6050 (LINEAS 84-104)
================================================================================

initMPU() (lineas 85-94):
  - Wire.begin(): arranca el bus I2C.
  - Wire.setTimeOut(100): 100 ms de espera maxima.
  - Escribe 0x00 en el registro 0x6B: saca el chip del modo dormida.
  - Escribe 0x08 en el registro 0x1B: configura el giroscopio a +-500 dps
    (grados por segundo). Con esa escala, 1 bit = 500/32768 = 0.01526 dps,
    por eso el factor 65.5 (cuentas por rad/s: 32768/500*57.2958 = 65.5).

leerGyroZ() (lineas 96-104):
  - Apunta al registro 0x47 (GYRO_ZOUT_H) y pide 2 bytes.
  - Une los dos bytes en int16_t raw (giro en el eje Z).
  - gyroZ = (raw / 65.5f) * DEG_TO_RAD -> pasa a rad/s.
  - Devuelve true si la lectura fue correcta, false si fallo el I2C.
  Es la unica medicion de orientacion del sistema: se usa en girar(),
  girarHastaDespejar(), en el re-cero del bias y en la odometria de rumbo.

15. ODOMETRIA: LINEAS EXACTAS Y EXPLICACION DETALLADA
================================================================================

La odometria es la estimacion de la posicion (x, y) y el rumbo (theta) del
robot integrando el movimiento de las ruedas. Corresponde a la Seccion 13.4
"Odometry" del libro Modern Robotics (paginas 548-550 del libro, paginas
568-570 del PDF), especialmente la ecuacion 13.34 para traccion diferencial.

---------- 15.1 Variables implicadas ----------

  Linea 71:  float theta = 0.0f;              -> rumbo en radianes
  Linea 77:  volatile long encIzq, encDer;    -> contadores de pulsos (ISR)
  Linea 78:  long prevIzq, prevDer;           -> ultima lectura de contadores
  Linea 79:  float x = 0.0f, y = 0.0f;        -> posicion en METROS
  Linea 81:  unsigned long tOdo;              -> marca de tiempo de odometria
  Linea 54:  const float CM_POR_SEG = 25.0f;  -> cm/s a PWM 190

  ISR, lineas 470-471:
    void IRAM_ATTR isrEncIzq() { encIzq++; }
    void IRAM_ATTR isrEncDer() { encDer++; }
    Se ejecutan automaticamente en cada flanco ascendente de los encoders.

  Sincronizacion, lineas 293-294 (dentro de iniciar()):
    prevIzq = encIzq;  prevDer = encDer;
    Evita contar como movimiento los pulsos ocurridos mientras estaba quieto.

---------- 15.2 ODOMETRIA POR ENCODERS (lineas 535-540) ----------

Codigo literal:

  535: long ei = encIzq, ed = encDer;
  536: float d = ((ei - prevIzq) + (ed - prevDer)) * 0.5f
  537:           * (2.0f * PI * 0.03f / 20.0f);
  537: prevIzq = ei;
  538: prevDer = ed;
  539: x += d * cos(theta);
  540: y += d * sin(theta);

Explicacion paso a paso:

  (ei - prevIzq) = pulsos del encoder izquierdo desde el ciclo anterior.
  (ed - prevDer) = pulsos del encoder derecho desde el ciclo anterior.

  Se SUMA n el promedio de ambos lados: el robot es diferencial, asi que
  la distancia del centro del chasis es la media de las dos ruedas:

      d_rueda = (Delta_izq + Delta_der) / 2

  El factor (2 * PI * 0.03 / 20) convierte pulsos a METROS:
      - radio de la rueda = 0.03 m (3 cm)
      - circunferencia = 2 * PI * 0.03 = 0.1885 m por vuelta
      - 20 pulsos por vuelta
      - metros por pulso = 0.1885 / 20 = 0.00942 m  (0.942 cm/pulso)

  Por tanto: d = pulsos_promedio * 0.00942 metros.

  Lineas 539-540 proyectan ese avance sobre el rumbo:
      x += d * cos(theta)
      y += d * sin(theta)
  Si theta = 0, todo el avance va en +x. Si theta = PI/2, va en +y.
  Es exactamente la idea de la ecuacion 13.34 (Vb = F * Delta_theta) seguida
  de la integracion q(k+1) = q(k) + Delta_q de las paginas 549-550.

  IMPORTANTE: theta NO se calcula con los encoders, sino con el giroscopio
  (lineas 562-571 y 204/237). El libro recomienda justamente complementar la
  odometria con otros sensores porque el error se acumula.

---------- 15.3 RUMBO CON GIROSCOPIO (lineas 562-571) ----------

Codigo literal:

  564: if (leerGyroZ()) {
  565:   unsigned long ahora = millis();
  566:   float dtg = (ahora - tGyro) / 1000.0f;
  567:   tGyro = ahora;
  568:   if (dtg > 0.0f && dtg < 0.3f) theta += (gyroZ - gyroBias) * dtg;
  569: }
  570: while (theta >  PI) theta -= 2 * PI;
  571: while (theta < -PI) theta += 2 * PI;

  - dtg es el tiempo desde la ultima lectura, en segundos.
  - gyroZ - gyroBias quita la deriva en reposo.
  - Se integra: theta += velocidad_angular * tiempo.
  - Se descartan saltos mayores a 0.3 s (por ejemplo despues de un HTTP que
    bloqueo el loop) para no introducir un salto falso.
  - Las lineas 570-571 mantienen theta en el rango [-PI, PI].

  tGyro se reinicia al terminar cada giro (lineas 203 y 236) y en setup
  (linea 508), para que el tiempo del giro no se cuente como avance.

---------- 15.4 ODOMETRIA POR TIEMPO (lineas 573-581) ----------

Codigo literal:

  575: float dt = (millis() - tOdo) / 1000.0f;
  576: tOdo = millis();
  577: if (dt > 0.0f && dt < 0.3f) {
  578:   float paso = (CM_POR_SEG / 100.0f) * dt;
  579:   x += paso * cos(theta);
  580:   y += paso * sin(theta);
  581: }

  - dt es el tiempo desde la ultima actualizacion, en segundos.
  - CM_POR_SEG = 25 cm/s; se divide entre 100 para pasar a METROS/s.
  - paso = 0.25 * dt metros es la distancia estimada.
  - Se proyecta sobre theta igual que con los encoders.
  - Se ignoran dt > 0.3 s para no contar distancia durante un bloqueo.

  Esta odometria se introdujo porque los encoders no reportaban de forma
  confiable: con esta estimacion el mapa muestra el recorrido aunque los
  contadores queden en cero.

---------- 15.5 REPORTAR AL MAPA ----------

---------- 15.6 OBSERVACION IMPORTANTE ----------

  Las dos odometrias (15.2 y 15.4) están activas al mismo tiempo cuando el
  robot avanza: ambas suman a x e y. Si los encoders funcionaran, la
  distancia se contaria DOS veces. En la practica los encoders no estan
  reportando (d = 0), por eso solo aporta la odometria por tiempo y el mapa
  se ve correcto. Si se conectan los encoders, conviene desactivar una de
  las dos o convertir la de tiempo en un respaldo condicional.
